# Contributing

Thank you for helping improve SFM PRO Enterprise.

## Branch Naming

- Use short, descriptive branch names.
- Recommended pattern: `type/short-description`
- Examples: `docs/readme-refresh`, `fix/backup-validation`

## Commit Messages

- Keep commits focused on a single concern.
- Use clear imperative summaries.
- Example: `docs: refresh production README`

## Coding Standards

- Preserve business logic, calculations, routing, storage schema, and UI behavior.
- Keep changes minimal and aligned with existing patterns.
- Prefer readable, defensive JavaScript and clear Markdown structure.

## Review Process

1. Open a focused pull request.
2. Summarize the change and any compatibility notes.
3. Link related documentation or issue references.
4. Wait for review before merging.

## Testing Process

- Verify documentation links and markdown formatting.
- Confirm image references resolve.
- Check that updates do not touch application runtime behavior.

## Release Process

1. Update documentation and metadata together.
2. Confirm version labels are consistent.
3. Validate repository structure and screenshots.
4. Record the release notes before publishing.
